# LTC · Личный кабинет преподавателя (v0.3)

Telegram Mini App для преподавателей + админка `/admin`. Node.js · Express 5 · MySQL. Реализует ТЗ v0.1 от 14.09.2026
(отметка посещаемости, оценок и темы → HollyHop через сервер-посредник) и добавляет разделы руководства из проекта «Академчасть».

## Запуск
```bash
npm install
cp .env.example .env        # заполнить BOT_TOKEN, HH_*, ADMIN_PASS, APP_URL
npm run init-db             # создаёт базу; на старой базе (v0.1/0.2) безопасно добавляет новые колонки
npm start
```
Демо без HollyHop: `HH_MOCK=1`, затем `node scripts/seed-demo.js <ваш_telegram_id> [id_координатора]`.
Тесты (нужна локальная MySQL/MariaDB, база `ltc_test` создаётся сама): `npm test`.

## Что добавлено из архива LTC
- **Роли** по Telegram ID: преподаватель · координатор · директор (`DIRECTOR_TG_IDS` или роль в `/admin`).
- **Обзор** (руководство): плитки, «сегодня не отмечено», столбцы по дням/филиалам/статусам, проблемные отметки.
- **Группы**: заполняемость, убыточные (`< LOW_FILL_THRESHOLD`), перебор, статус отметки, карточка группы (состав + посещаемость), назначение замены.
- **Преподаватели**: нагрузка, посещаемость, дисциплина отметок; **«Профиль»** преподавателя за месяц.
- **CSV-выгрузки** (группы, преподаватели, отметки, сотрудники).
- **Выгрузка в Excel** (`/admin` → «Выгрузка», период до 62 дней): «Расписание» — уроки преподавателей по дням из HollyHop (`GetEdUnits` с `queryDays`), ак. часы (45 мин), ставка и ЗП формулой; «Фактические отметки» — отправленные из кабинета уроки по дням. Листы: Иностранные / Местные — по ФИО: латиница — иностранный, кириллица — местный.
- **Отчёты по ученикам** (период до года, выпадающий список преподавателей): во «Тестах учеников» вкладки (и листы Excel) «По преподавателям» — ФИО ученика и его средний % тестов (ежедневный за каждый урок + доп. тесты) в колонке ≥80% / 70–79% / <70%; «Посещаемость» — по преподавателю или по всем: сколько учеников с 1 и 2 пропусками и с долей пропусков ≥15%, ≥30%, ≥50%, плюс лист «Пропуски учеников». Урок, отмеченный двумя преподавателями, в «все» считается один раз. Все вкладки «Тестов учеников» и Excel фильтруются по филиалу, уровню группы и преподавателю (`branch`, `level`, `teacher`); «Отметки» — тоже по филиалу, уровню и преподавателю.
- **Клиент HollyHop**: повторы с jitter, `Retry-After`, таймаут, ограничение частоты, кэш 30 с, типизированные ошибки.
- **Безопасность**: CSP, `nosniff`, `no-store` для API, лимит запросов, лимит неверных паролей админки, лог без query/initData, `/healthz`.
- **Дизайн**: бренд-система LTC (Manrope, #883DF7→#C558F8, тёмная/светлая тема, только столбцы/плитки/таблицы), безопасные зоны, кнопка «Назад» Telegram.

## Правила ввода (решения Учебного отдела, разд. 5 ТЗ)
Ежедневный тест, тема урока и домашнее задание обязательны всегда, `COMMENT_MAX_LEN` — длина темы; тесты — только для присутствовавших. ДЗ — одно текстовое поле на всю группу под темой урока (с КТП не связано) и уходит в HollyHop в commentHtml под темой: «Дз/Hw: …».

Коины: после записи тестов ученику прибавляются коины в пользовательское поле «Коины» (`HH_COINS_FIELD`) — GetStudents → EditUserExtraFields. Ежедневный тест: (ДЗ + активность) × 2; Progress Test, Final Test, Revise&Check, File Test NEF, Quick Test NEF: 60–80 % от максимума → +10, от 80 % → +20 (Entry test — без коинов).

Города: фильтры в админке и мини-аппе — по городу, а не по филиалу. Офисы HollyHop с Id из `HH_ALMATY_OFFICE_IDS` (по умолчанию `7,9`) — Алматы, остальные — Астана.

## Тестирование в HollyHop
Все тесты — персональные: ежедневный тоже пишется методом `AddEditPersonalTestResult` (тип 131/132, время занятия, `teacherId` преподавателя) вместе с посещаемостью (`SetStudentPasses`), в той же идемпотентной очереди.

| Что | Значение |
|---|---|
| Группа | `edUnitId = 31`; список групп (ID групп, не типов теста!) — `HH_TEST_EDUNIT_IDS` (через запятую). Пусто — тест пишется для всех групп |
| Тип теста | `131` — иностранный преподаватель (lang=en), `132` — местный |
| Навыки 131 (Foreign) | 8 Was present for (min) — всегда 45, в интерфейсе скрыт · 11 Homework · 9 Engagement · 10 Discipline — макс. 5, порог 4 |
| Навыки 132 (Local) | 8 Was present for (min) — всегда 45, в интерфейсе скрыт · 13 Домашнее задание · 9 Активность · 10 Дисциплина — макс. 5, порог 4 |
| Доп. тест | `AddEditPersonalTestResult`, не больше одного на урок, по желанию: Progress Test, Final Test, Entry test (тип 124–129), Revise&Check (тип 5–7), File Test NEF (кат. 45, File 1–12 — тип 137–148), Quick Test NEF (кат. 2, тип 2: Grammar 20, Vocabulary 20, Pronunciation 10). Конфигурация — `src/config/personalTests.js` |

Ежедневный тест обязателен для присутствовавших (`TEST_REQUIRED` больше не читается). Набор навыков типа теста отправляется целиком; баллы не больше максимума, иначе 422. Тесты не пишутся пропустившим. В `commentHtml` уходит тема урока (экранируется). Порог успешности в мини-аппе не подсвечивается — только метрика «прошли порог» в статистике. Конфигурация — `src/config/testing.js`.

## Исправление отметки (через одобрение)
Своя отметка после сохранения — только чтение. Если преподаватель ошибся, он открывает урок (из «Занятий» или из «Профиля → Последние занятия») и нажимает «Запросить исправление» с причиной. Запрос появляется в `/admin` → «Исправления»; одобрение открывает правку на `EDIT_WINDOW_HOURS` часов (по умолчанию 72) — один раз, преподавателю приходит сообщение в Telegram.

Что можно исправить: тему, ДЗ, тему КТП, «был/пропуск», баллы ежедневного теста, доп. тест (баллы, другой тип или убрать совсем).
Как это уходит в HollyHop: посещаемость перезаписывается (`SetStudentPasses`); тесты правятся по Id результата (`AddEditPersonalTestResult` с `id`) — Id сохраняются при записи (`submissions.hh_results`), у старых отметок ищутся через `GetPersonalTestResults`; коины — начисляется разница с уже начисленным (может быть списание).
**Удаления в API HollyHop нет:** если тест убран (ученик стал «пропуск», доп. тест удалён или заменён другим типом), результат попадает в «Исправления → Удалить в HollyHop вручную» с Id результата — его удаляют в HollyHop руками и отмечают «Удалено». Прежняя и новая версия отметки пишутся в аудит (`edit`), в `/attendance-api` исправленная запись приходит по `updated_since`.

## API для сервиса менторов (`/integration-api`)
Ключ — `INTEGRATION_KEY` в `.env` (заголовок `X-Api-Key` или `Authorization: Bearer`); без ключа API закрыт.

- `GET /integration-api/absences?from=YYYY-MM-DD&to=YYYY-MM-DD` (период до 366 дней; по желанию `city`, `level`, `teacher`) — «Ученики с пропусками» по всем преподавателям: `studentId` (HollyHop ID), `student`, `groups` [{id, name}], `lessons`, `absent`, `rate`, `feedback` (последняя обратная связь за пересекающийся период или `null`).
- `POST /integration-api/absence-feedback` — массив (или `{ items: [...] }`, до 1000): `studentId`, `period: { from, to }`, `status` (строка до 64), `feedbackAt` (ISO 8601 с часовым поясом, например `2026-12-02T10:00:00Z`), по желанию `student`, `groups`, `lessons`, `reason`, `mentor`. Хранится в `absence_feedback`, ключ — ученик + период: повтор обновляет запись, более старая `feedbackAt` новую не затирает. Ошибка хоть в одной записи → 400 `{ error: 'bad_items', errors: [{ index, field }] }`, ничего не сохраняется. История — в аудите (`absence_feedback`).

Статус, причина и дата обратной связи видны в админке («Выгрузка → Тесты учеников → Посещаемость») и в Excel-листе «Пропуски учеников».

## API для кабинета ученика и ботов-кураторов (`/attendance-api/v1`)
Только чтение (GET), ключ `ATTENDANCE_API_KEY` (`Authorization: Bearer` или `X-Api-Key`), без ключа API закрыт. Лимит — `ATTENDANCE_API_RATE_PER_MIN` (60/мин с IP) и `ATTENDANCE_API_MAX_CONCURRENT` (3 одновременных), по желанию IP-allowlist `ATTENDANCE_API_IPS`.
Эндпоинты: `/lessons` (журнал), `/tests` (доп. тесты), `/students`, `/groups`, `/teachers`, `/meta`; все ключи — HollyHop (ClientId, EdUnit, Id преподавателя), курсорная пагинация и `updated_since`. Документация для потребителей — [docs/attendance-api.md](docs/attendance-api.md).
