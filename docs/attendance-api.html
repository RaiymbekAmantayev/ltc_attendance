4Как правильно пользоваться API

4.1 Выгрузка по курсору (/lessons, /tests)

Идите по page.next_cursor, пока он не станет null. Курсор привязан к фильтрам — не меняйте параметры между страницами.

Страница может быть короче limit и даже пустой при has_more: trueЗа один вызов сервер просматривает не больше 2000 отметок, чтобы не нагружать базу. Это нормально: просто запросите следующую страницу.
import os, time, requests

BASE = "https://attendance.ltsastana.kz/attendance-api/v1"
S = requests.Session()
S.headers["Authorization"] = f"Bearer {os.environ['ATT_TOKEN']}"

def get(path, **params):
    for attempt in range(5):
        r = S.get(BASE + path, params=params, timeout=60)
        if r.status_code == 429:                # лимит: ждём, сколько сказал сервер
            time.sleep(int(r.headers.get("Retry-After", "5")))
            continue
        if r.status_code >= 500:
            time.sleep(2 ** attempt)
            continue
        r.raise_for_status()                    # 400/401/403 — ошибка запроса, не повторять
        return r.json()
    raise RuntimeError(f"{path}: не удалось после повторов")

def iterate(path, **params):
    cursor = None
    while True:
        extra = {"cursor": cursor} if cursor else {}
        page = get(path, **params, limit=500, **extra)
        yield from page["data"]
        cursor = page["page"]["next_cursor"]
        if not cursor:
            return

for rec in iterate("/lessons", date_from="2026-11-01", date_to="2026-11-14"):
    save(rec)                                   # upsert по rec["record_id"]

Node.js 18+:

const BASE = 'https://attendance.ltsastana.kz/attendance-api/v1';
const headers = { Authorization: `Bearer ${process.env.ATT_TOKEN}` };
const sleep = ms => new Promise(r => setTimeout(r, ms));

async function get(path, params) {
  for (let attempt = 0; attempt < 5; attempt++) {
    const res = await fetch(`${BASE}${path}?${new URLSearchParams(params)}`, { headers });
    if (res.status === 429) { await sleep(Number(res.headers.get('retry-after') || 5) * 1000); continue; }
    if (res.status >= 500) { await sleep(2 ** attempt * 1000); continue; }
    if (!res.ok) throw new Error(`${path}: ${res.status} ${await res.text()}`);
    return res.json();
  }
  throw new Error(`${path}: не удалось после повторов`);
}

async function* iterate(path, params = {}) {
  let cursor;
  do {
    const page = await get(path, { ...params, limit: 500, ...(cursor ? { cursor } : {}) });
    yield* page.data;
    cursor = page.page.next_cursor;
  } while (cursor);
}

4.2 Инкрементальная синхронизация (раз в час)

  1. Первый запуск: полная выгрузка /lessons и /tests за нужный период — по месяцам, период не длиннее 366 дней.
  2. Сохраните у себя max(updated_at) из полученных записей.
  3. Следующий запуск: updated_since = сохранённое значение минус 5 минут (запас на отметки, которые сохранялись во время выгрузки).
  4. Записи upsert-ите по record_id / test_id: из-за запаса часть придёт повторно.

Отметки после сохранения не редактируются, поэтому updated_at — время появления записи. Удалений нет.

4.3 Точечный запрос по ученику (бот-куратор, «Мой профиль»)

GET /students?hollyhop_client_id=801                       → группа, уровень, преподаватель
GET /lessons?hollyhop_client_id=801&date_from=2026-10-15   → посещаемость, баллы, темы, ДЗ
GET /tests?hollyhop_client_id=801&date_from=2026-05-14     → тесты за полгода

Кэшируйте ответ у себя хотя бы на несколько минут: данные меняются только тогда, когда преподаватель отмечает урок.

4.4 Правильно

  • Запросы только с сервера, токен — в секретах
  • Большие объёмы — через курсор с limit=500
  • Синхронизация через updated_since
  • При 429 ждать Retry-After
  • Дедупликация по record_id / test_id

4.5 Не делайте так

  • Опрос чаще раза в 5–10 минут для синхронизации
  • Больше 2–3 параллельных запросов
  • Перебор всех учеников по одному через hollyhop_client_id
  • Запросы из браузера или мини-аппа
  • Повторы при 400 / 401 / 403

6Безопасность и персональные данные

  • Доступ только по токену и только по HTTPS. Токен сравнивается за постоянное время и не пишется в логи.
  • Ответы идут с Cache-Control: no-store: прокси и клиенты не кэшируют персональные данные.
  • IP-allowlist: пришлите исходящие IP ваших агентов — включим, остальные получат 403 ip_not_allowed.
  • Только чтение и только поля из этого документа: без Telegram ID, телефонов и т.п.
  • Токен API менторов и этот токен разные: один не открывает другой API.
